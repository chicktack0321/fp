# FP技能検定 作問プロンプト（完全版）

作問AI（Claude等）に渡すプロンプト。`{{級}}` `{{科目}}` `{{細目コード}}` `{{出題形式}}`
`{{難易度}}` `{{問題数}}` `{{法令基準日}}` `{{既存キーワード一覧}}` を埋めて使う。

出力は `batches/FP3/` または `batches/FP2/` に置き、
`python scripts/merge_questions.py batches/FP3/<file>.json` でシードへ取り込む。
`questionId` はAIに振らせない（バッチをまたいだ連番を管理できず衝突するため。採番はスクリプトが行う）。

## 級による違い（ここを間違えると丸ごと作り直しになる）

| | 3級 | 2級 |
| --- | --- | --- |
| 学科の形式 | ○×式（2択）と三答択一式（3択） | 四答択一式（4択） |
| `choices` のキー | `A`/`B` または `A`/`B`/`C` | `A`/`B`/`C`/`D` |
| 問われる深さ | 制度の名称・数値・区分 | 要件・例外・計算・複合論点 |
| バッチの置き場所 | `batches/FP3/` | `batches/FP2/` |

**○×式の選択肢は `A`=「正しい」、`B`=「誤り」で固定する。** アプリはこの並びを
シャッフルせずそのまま出す（本試験と同じ順序にするため）。逆にすると画面上で
「誤り」が先に並ぶ。

# 指示
あなたは国家検定「FP技能検定（ファイナンシャル・プランニング技能検定）」の専門作問者です。
日本FP協会・金融財政事情研究会が公表している試験範囲に準拠した学科試験の問題を生成してください。

# 作成条件
1. 級: {{級}}（3級 または 2級）
2. 形式: {{出題形式}}
   - 3級の場合: 「○×式」（選択肢 A=正しい / B=誤り）または「三答択一式」（選択肢 A, B, C）
   - 2級の場合: 「四答択一式」（選択肢 A, B, C, D）
3. レベル: 本試験の学科と同等
   - 3級 … 制度の名称・数値・区分を問う
   - 2級 … 適用要件・例外・計算・複数制度の組合せを問う
4. 解説: 正解の理由だけでなく、すべての誤答選択肢について「なぜ誤りか」「正しくは何か」を明記すること
5. 法令基準日: {{法令基準日}} 時点で施行されている制度に基づくこと。
   基準日より後に施行される改正は使わない。基準日より前の旧制度の数値も使わない。

# 今回の生成範囲
- 科目: {{科目}}
- 細目: {{細目コード}}（下記コード表から）
- 難易度: {{難易度}}
  1=基礎: 制度の名称・数値をそのまま問う
  2=標準: 要件・例外・適用の可否を問う（本試験の中心）
  3=応用: 計算、複数制度の組合せ、実技で問われる事例判断
- 問題数: {{問題数}}問

# 品質基準（1問ごとに自己検証すること）
- 正解が一意に定まること。「最も適切なもの」形式では、他の選択肢が明確に誤りであること。
  **誤答のつもりの選択肢が実は正しい記述になっていないか**を1つずつ確かめること
  （FPは「正しいが問いに答えていない」選択肢を作りやすく、そのまま出すと問題が成立しない）
- 誤答選択肢は実在する制度・数値の説明とし、もっともらしく作ること。
  よい誤答は「別の制度の正しい数値」「1つ前の年度の数値」「似た制度の要件」である
- すべての解説が事実として正しいこと。誤答の解説では、その選択肢が指す制度の正しい内容を必ず述べること
- 問題文は最大300字、選択肢は各最大120字
- 計算問題は解説内に計算過程（式と数値）を示し、検算すること
- 数値は法令基準日時点のものを使うこと。毎年改定される額（年金額、在職老齢年金の支給停止調整額、
  各種の上限額など）は、改定のたびに問題が誤りになるため、**できるだけ仕組みを問う形にする**
- 制度名は正式名称を使うこと（例: 「住宅ローン控除」ではなく「住宅借入金等特別控除」を少なくとも1度示す）

## 運用メモ

- 細目単位・20問前後のバッチで生成する（偏りの検出とレビューのしやすさのため）
- 生成後は `docs/design-spec.md` のレビューチェックリストで**必ず人手レビュー**してから
  シードに取り込む。国家検定の対策アプリで解説が誤っていると、利用者は誤った知識を
  「正解」として覚える。特に次は機械では検出できない
  - **税額・年金額の数値** — 毎年改定される。法令基準日と突き合わせる
  - **計算問題** — 検算する
  - **正解の一意性** — 誤答のつもりの選択肢が正しい記述になっていないか
- 取り込みと検証:

  ```bash
  python scripts/merge_questions.py batches/FP3/pension-01.json
  python scripts/validate_seed.py FP3
  python scripts/rebalance_answers.py FP3   # 正解の位置が偏っていれば
  ```

- ○×式は「正しい」が正解の問題ばかりになりやすい。読まずに○を選んで当たってしまうため、
  `validate_seed.py` が半々から大きく外れていないかを報告する。
  偏っていたら**問題文を否定形の誤った記述に書き換えて**直す
  （選択肢の入れ替えでは直せない。`rebalance_answers.py` は○×式を対象外にしている）
- 法令改正のたびに `FPn/AppFlavor.swift` の `lawBasisDate` とシードの `lawBasisDate` を
  同時に更新する。片方だけだと検証が落ちる（そのための検査を入れてある）
- 3級と2級は**同じ細目コードを共有している**。同じ論点を両方の級で出してよいが、
  問われる深さを変えること（3級=数値、2級=要件と例外）
