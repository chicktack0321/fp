# FP技能検定 特訓（3級 / 2級・完全オフライン）

国家検定「FP技能検定（ファイナンシャル・プランニング技能検定）」の学科対策アプリ。
サーバー通信・アカウント登録なし。**3級と2級を別々のアプリとして出し、ソースは1本で共用する。**

`C:\System_Dev\ITpassport`（ITパスポート特訓）の骨格を流用し、
出題ドメインをFP技能検定に差し替えたうえで、1リポジトリから2つのアプリを作る構成にした。

## ビルド方法（Mac実機なし・GitHub ActionsのmacOSランナーを使用）

`.xcodeproj` はコミットせず、[XcodeGen](https://github.com/yonaskolb/XcodeGen) が
`project.yml` から毎回生成する。1つの `.xcodeproj` に6ターゲット（アプリ2・ユニットテスト2・UIテスト2）と
2スキームが入る。

### CIでビルドとテストを確認する

GitHub にpushすると `.github/workflows/ios-build.yml` が動く。2段構成になっている。

1. **validate-seed**（Ubuntu）: `scripts/validate_seed.py` で3級・2級の問題データを検証する。
   macOSランナーは分単価が高い（privateリポジトリでは10倍消費）ため、
   シードの形式ミスでmacOSジョブを2つとも無駄にしないよう手前で落とす
2. **build**（macOS・級ごとのマトリクス）: ビルド + ユニットテスト + UIテスト。
   UIテストがシミュレータ上で画面を操作し、[`xcparse`](https://github.com/ChargePoint/xcparse) が
   `.xcresult` からPNGを抽出する。Actionsの実行結果ページ → Artifacts欄の
   **`ui-screenshots-FP3App`** / **`ui-screenshots-FP2App`** をダウンロードすると、
   実際に描画された画面を確認できる

`fail-fast` を切ってあるので、片方が落ちてももう片方の結果まで出る。
ソースを共有しているため、片方だけ通っても意味がない。

### App Store用のスクリーンショットを撮る

Actionsタブ → **App Store Screenshots** ワークフロー → **Run workflow**（手動トリガー）。
撮影するアプリと、使うシミュレータを入力で指定する（既定は `iPhone 16 Pro Max`）。

`ios-build` のUIテストは空いているシミュレータを拾って撮るため、画素数が実行ごとに変わる。
App Store Connect は画素数が決まっている（iPhone 6.9インチは 1320x2868 か 1290x2796）ので、
こちらは機種を固定し、提出に使う5枚だけを `scripts/collect_appstore_screenshots.py` で選んで
画素数を検査する。

3級と2級は出題形式も問題文も違うため、**画像は必ず級ごとに撮る**。
片方の画像をもう片方のストアに載せると、実物と違う画面を掲載したことになり審査で指摘される。

- 時刻・バッテリー・電波は `simctl status_bar` で 9:41・満充電・最大に固定する
- Artifacts欄の **`appstore-screenshots-FP3App`** が提出用の5枚
  （ホーム / 演習の出題 / 全選択肢の解説 / 問題一覧 / 学習履歴）
- **`appstore-screenshots-raw-FP3App`** には撮った全画面が入る

### 問題データをローカルで検証する

```bash
python scripts/validate_seed.py        # 3級・2級の両方
python scripts/validate_seed.py FP3    # 級を指定
```

形式の検査に加えて、科目別・難易度別・形式別の収録数と、正解の位置の偏りを出す。
級ごとの期待値（IDの接頭辞・ありえる選択肢の数・法令基準日）は `FPn/AppFlavor.swift` から読むので、
Swift側とPython側で数値が食い違うことがない。

同じ検査は `FPAppTests/SeedValidationTests.swift` からも走る
（CIでスクリプトを回すだけだと、手元でシードを編集したときに気付けないため）。

### TestFlightへ配信する

**初回は [docs/testflight-setup.md](docs/testflight-setup.md) の手順を先に済ませること。**
GitHub Secrets の登録、App ID の登録、App Store Connect でのアプリ登録が必要で、
どれか欠けるとアップロードの段階で失敗する。App ID とアプリ登録は**3級・2級それぞれに必要**。
バンドルIDは公開後に変更できないため、アプリを登録する前に確定させる。

設定が済んでいれば、Actionsタブ → **TestFlight** ワークフロー → **Run workflow** で
配信するアプリを選んで実行する。pushのたびに配信するとビルドが溜まりテスターへの通知も続くため、
意図的に手動トリガーにしている。

ビルド番号にはワークフローの実行番号を使う。App Store Connectは同じ（バージョン, ビルド番号）の
組を二度受け付けないため、必ず増える値が要る。表示用のバージョンを上げるときは
`project.yml` の `MARKETING_VERSION` を変更する。

配信前に、**同梱された問題データのIDが選んだ級の接頭辞で始まっているか**まで検査している。
3級のアプリに2級の問題が入っていても画面上は普通に動いてしまうため、機械で止める。

## 出題ドメイン

学科試験は6科目から10問ずつ・計60問。**合否は60問の総得点だけで決まり、科目ごとの足切りは無い。**

| 科目 | 細目の例 |
| --- | --- |
| ライフプランニングと資金計画 | 社会保険・公的年金・資金計画・FPの倫理と関連法規 |
| リスク管理 | 生命保険・損害保険・第三分野・保険と税金 |
| 金融資産運用 | 預貯金・投資信託・債券・株式・外貨・金融商品と税金 |
| タックスプランニング | 所得税の仕組み・所得控除・申告と納付・法人税・消費税 |
| 不動産 | 不動産の取引・法令上の規制・不動産の税金・有効活用 |
| 相続・事業承継 | 贈与・相続の法律と税金・財産評価・事業承継 |

科目ごとの足切りが無いのに科目別習熟度をホームの主表示に置いているのは、
6科目が扱う制度が互いにほぼ独立していて、**手つかずの科目が1つあると本試験でそのまま10問落とす**ため。
「総合40%」からは次の手が決まらないが、「相続だけ10%」なら決まる。

細目（`MidCategory`）は40コードで、3級と2級で共通。出題範囲の区分は両級で同じで、
違うのは問われる深さだけなので、級ごとに分けると同じ論点に別のコードが付いてしまう。

## 法令基準日

FP技能検定は試験日ではなく**法令基準日時点の制度**で出題され、税制・社会保険の数値は毎年変わる。

- シードのトップレベルと `FPn/AppFlavor.swift` の両方に `lawBasisDate` を持つ
- **両者が一致することをテストと検証スクリプトが確かめる。** ずれていると
  「2026年4月1日基準です」と表示しながら別の年度の数値を出題することになり、利用者は気付けない
- 改正対応のときは、シード・AppFlavor・該当する問題の3つを同時に直す

## 問題データの作り方

```bash
# 1. docs/question-authoring-prompt.md のプロンプトでバッチを生成し、人手レビューする
# 2. 取り込む（questionId はここで採番される）
python scripts/merge_questions.py batches/FP3/pension-01.json

# 3. 検証する
python scripts/validate_seed.py FP3

# 4. 正解の位置が偏っていればならす
python scripts/rebalance_answers.py FP3
```

細目単位・20問前後のバッチで生成すると、偏りの検出とレビューがしやすい。

### questionId は改名禁止

`<級>_<細目コード>_<4桁連番>`（例: `FP3_PENSION_0042`）。**公開後の改名は禁止**。
改名は「削除＋新規」になり、その問題の学習履歴が全ユーザーで失われる。
問題文・選択肢・解説の修正は自由（IDが同じなら履歴は保持される）。

誤りが見つかった問題は、削除ではなくシードから外す。Seederは孤児進捗を許容する設計になっている。

## アイコン

```bash
python scripts/make_app_icon.py   # 3級・2級の両方を書き出す
```

| ファイル | 役割 |
| --- | --- |
| `docs/assets/fp3-icon-source.png` | 3級の元画像（オレンジ）。**絵柄を変えるときはこちらを直す** |
| `docs/assets/fp2-icon-source.png` | 2級の元画像（緑） |

スクリプトは絵柄を扱わない。やるのは「App Storeに出せる形かどうかを検査して書き出す」ことだけで、
1024x1024の正方形・アルファなし・角丸の焼き込みなしを確かめ、
さらに**絵柄がAppleの角丸マスクの外にはみ出していないか**を見る。
はみ出しはビルドも審査も通ってしまい、ホーム画面に並べて初めて気付く類の欠陥なので、
書き出しのたびに機械で止める。

アプリ内ロゴ（`AppLogo` @1x/2x/3x）も同じ元画像から書き出す。
こちらは `cornerRadius: 10` の浅いクリップなので、角丸なしの正方形でないと角の残りが見える。

## 課金と試用

無料で配布し、買い切りのApp内課金で「標準問題」と「応用問題」を出題対象に加える。
**広告とサブスクリプションは実装しない。**

初回起動から7日間は全問を試せる。**期間が終わっても演習は使えるまま**で、
変わるのは出題対象が基礎の問題だけになること。問題一覧での閲覧・検索・解説の読み直しは常に全問できる。
機能を止める作りにしていないのは、一定期間後に動かなくなる体験版が App Review の拒否対象であり、
教育カテゴリでは「使えなくなった」という★1レビューを最も招くため。

2級は全体に難しいため作問が応用に寄りやすいが、**基礎が0問になると未購入の利用者が
演習を1問も始められない**。これはユニットテストで落とすようにしてある。

### 問題内容のレビューが必要な理由

同梱の問題はAIが生成したもので、機械検証（形式・ID重複・問題文の重複・科目と細目の
対応・解説の有無と書き出し・文字数・級と選択肢数の整合）は通っているが、
**書かれている内容が正しいかどうかは検証されていない**。

国家検定の対策アプリで解説が誤っていると、利用者は誤った知識を「正解」として覚える。
公開前に設計仕様書 §9.1 のチェックリストで全問を確認すること。特に次の3点は
機械では検出できない。

- **税額・年金額の数値** — 毎年改定される。法令基準日と突き合わせる
- **計算問題** — 検算する
- **正解の一意性** — 誤答のつもりの選択肢が、実は正しい記述になっていないか
